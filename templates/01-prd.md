# Phase 1: PRD（产品需求文档）

> **目的**: 定义「要解决什么问题」和「做完后是什么样子」
> **输出物**: 填写完成的本文档，存放到 `<project>/docs/01-prd.md`

---

## 1.0 对齐锚点（必填）

> **在写 PRD 之前，先写下你不可妥协的核心约束。**
> 这些锚点是你判断 AI 产出是否跑偏的永恒基准，比规格更高层级。
> 详见 [APPENDIX-human-in-the-loop.md](APPENDIX-human-in-the-loop.md) A.1 节。

| # | 约束类型 | 不可妥协的约束 |
|---|---------|---------------|
| 1 | 业务边界 | （例：绝对不做 X / 只做 Y） |
| 2 | 技术边界 | （例：支付只用支付宝 / 必须自托管） |
| 3 | 架构边界 | （例：单体应用 / AI 只做分发不做业务逻辑） |
| 4 | 质量边界 | （例：所有资金操作必须幂等 / 测试覆盖 ≥90%） |
| 5 | 范围边界 | （例：MVP 必须一个周末能部署 / 区块链不在范围内） |

**规则**: 锚点不可在 AI 对话中被"更好的建议"隐式修改。修改锚点必须你主动决定并记录。

## 1.7 先搜索，再建造 (Search Before Building)

> **核心理念**: 建造前的搜索成本接近于零，不搜索的成本是重复造轮子

### 三层知识体系

在定义需求前，先在以下三个层次搜索：

#### Layer 1: 经过验证的 (Tried and True)
标准模式、经过实战检验的方法、广泛传播的知识

| 搜索项 | 搜索位置 | 预期结果 |
|--------|---------|---------|
| 标准库/框架功能 | 官方文档 | 是否有内置解决方案 |
| 常见设计模式 | 技术书籍/经典文章 | 是否有标准模式可用 |
| 公司内现有实现 | 内部代码库 | 是否有可复用组件 |

#### Layer 2: 新颖流行的 (New and Popular)
当前最佳实践、博客文章、生态系统趋势

| 搜索项 | 搜索位置 | 注意事项 |
|--------|---------|---------|
| 最新技术方案 | GitHub、技术博客 | 批判性审视，避免狂热 |
| 社区讨论 | Stack Overflow、Reddit | 看评论区的反对意见 |
| 竞品分析 | 竞争对手产品 | 学习但不要复制缺陷 |

#### Layer 3: 第一性原理 (First Principles)
从具体问题推理得出的原创观察

| 思考问题 | 记录方式 |
|---------|---------|
| 大家都在做的假设是什么？ | 写下来 |
| 这些假设在当前场景下还成立吗？ | 验证/质疑 |
| 如果打破这些假设，会有什么新方案？ | 头脑风暴 |

### Eureka Moment（顿悟时刻）

最有价值的搜索成果是发现传统方法的错误。

**当找到时**:
- [ ] 命名它
- [ ] 记录它

## 1.8 代码库探索 (Explore Agent) - 如有现有代码

> **适用场景**: 项目涉及现有代码库修改或集成  
> **目标**: 快速理解现有代码结构和模式

### 探索清单

在编写 PRD 前，对现有代码库进行快速探索：

| 探索项 | 方法 | 输出 |
|--------|------|------|
| **项目结构** | `ls -la`, `find . -type f -name "*.md"` | 目录结构图 |
| **技术栈** | 检查 `package.json`, `Cargo.toml`, `requirements.txt` | 技术栈清单 |
| **核心模块** | Glob 搜索 `src/**/*.rs` 或 `src/**/*.ts` | 模块依赖图 |
| **API 接口** | Grep 搜索 `route`, `endpoint`, `handler` | API 列表 |
| **数据模型** | 搜索 `struct`, `interface`, `type` 定义 | 核心数据结构 |
| **配置管理** | 检查 `.env`, `config.yaml`, `settings.json` | 配置项清单 |

### 探索原则 (借鉴 Explore Agent)

- ✅ **只读探索**: 不修改任何文件
- ✅ **并行搜索**: 同时搜索多个模式提高效率
- ✅ **由广到深**: 先整体结构，后具体实现
- ✅ **记录发现**: 将关键发现记录到文档

```markdown
- 复用机会: 
- 集成点: 
- 潜在风险: 
```
