# Phase 0: Business Validation（商业验证）

> **目的**: 在写代码之前，验证商业想法值得构建  
> **适用场景**: 你有一个想法，但不确定是否该投入开发  
> **输出物**: 验证过的商业模式 + 手动交付流程  
> **核心原则**: Processize before Productize（先流程化，后产品化）

---

## 0.1 找到社区（Find Community）

> 产品始于人，不是想法。

### 明确你的受众

| 问题 | 你的回答 |
|------|---------|
| 谁具体有这个痛点？ | （例：不是"企业"，而是"自由设计师"） |
| 他们在哪里聚集？ | （论坛、Reddit、Slack、微信群） |
| 你能叫出 10 个具体的人名吗？ | |

### 验证标准

- [ ] 能描述一个具体的人（名字、职业、日常）
- [ ] 知道他们在哪里讨论相关问题
- [ ] 已经与至少 3 人交流过

**如果不能回答，回到这一步继续寻找。**

---

## 0.2 验证想法（Validate Idea）

> 验证通过销售，不是构建。

### 问题定义

| 问题 | 回答 |
|------|------|
| 他们现在怎么解决这个问题的？ | （现有方案 = 你的真正竞争对手） |
| 这个问题有多痛？ | （轻微烦恼 vs 燃眉之急） |
| 他们愿意付费让这个问题消失吗？ | |

### 验证测试

**最低标准**:
- [ ] 与 10 个潜在客户交谈
- [ ] 至少 3 人表示愿意付费（或已付费）
- [ ] 知道他们愿意付多少钱

### 四个构建前问题

1. **能在一个周末内发布吗？** 如果不能，减少范围。
2. **能让客户生活好一点吗？** 这是 MVP 的及格线。
3. **客户愿意付费吗？** 从第一天开始盈利。
4. **能快速得到反馈吗？** 为能告诉你是否有效的人构建。

---

## 0.3 流程化（Processize）

> 每个伟大产品都始于手工完成工作。

### 三阶段演进

```
Manual（手工） → Processized（流程化） → Productized（产品化）
     ↓                ↓                      ↓
 你亲自做         写在纸上的流程          自动化软件
 逐个服务客户      任何人都能执行          客户自助使用
```

**例子**：Gumroad 开始前，Sahil 手动收集 PayPal 邮箱，一个一个付款给创作者。

### 设计手动版本

回答三个问题：

| 步骤 | 描述 |
|------|------|
| **输入** | 客户给你什么？（邮件、文件、需求描述） |
| **处理** | 你做什么？（写在你的"魔法流程纸"上） |
| **输出** | 客户得到什么？（交付物、结果、价值） |

### 流程文档模板

```
## [产品名] 手动流程

### 客户输入
客户发送：[具体格式]

### 处理步骤
1. 接收并记录到 [工具：Airtable/Google Sheets]
2. 处理：[具体动作]
3. 检查：[质量标准]
4. 交付：[方式和格式]

### 交付输出
客户收到：[具体结果]

### 时间
单次交付耗时：[X 分钟/小时]
```

## 0.4 MVP 范围定义

### 构建什么

**大多数互联网应用只是表单和列表（CRUD）。** 你的 MVP 不应比这更复杂。

| 功能 | 是否包含 | 理由 |
|------|---------|------|
| 核心功能（一个） | ✅ 必须 | 解决主要痛点 |
| 用户系统 | ❌ 延后 | 用 Google/邮箱登录 |
| 支付系统 | ⚠️ 简化 | 用 Stripe Link / 支付宝收款码 |
| 后台管理 | ❌ 延后 | 用 Airtable / 飞书表格 |
| 数据分析 | ❌ 延后 | 手动统计 |

### 四个"不构建"原则

1. **不构建**：你现在可以手动完成的事情
2. **不构建**：不确定客户是否需要的东西
3. **不构建**：为了"完整"而加的功能
4. **不构建**：需要超过一个周末的工作量

## 0.5 定价策略

> 免费和 1 美元之间有巨大差异（零价格效应）。

### 定价检查清单

- [ ] 从第一天开始收费
- [ ] 价格基于价值，不是成本
- [ ] 有明确的付费版本（即使是$1）
- [ ] 知道为什么客户愿意付这个价钱

### 简单定价模型

| 层级 | 价格 | 包含 |
|------|------|------|
| 免费版 | ¥0 | 基本功能，限制用量 |
| 付费版 | ¥X/月 | 核心功能，无限制 |

**不要**：免费增值、复杂分级、企业版（除非你真有企业客户）

## 0.6 获取前 100 个客户

> 一次获取一个客户。不要广告。

### 获取策略

| 阶段 | 方法 | 目标 |
|------|------|------|
| 第 1-10 个 | 直接联系你认识的人 | 验证需求 |
| 第 11-50 个 | 在社区中分享，私信感兴趣的人 | 收集反馈 |
| 第 51-100 个 | 口碑传播，请求推荐 | 验证增长 |

### 每日行动

- [ ] 每天联系 5 个潜在客户
- [ ] 每天与 1 个客户深度交流
- [ ] 每周请求 1 个客户推荐

---

## 0.7 转向 Phase 1 的标准

**当你满足以下条件时，可以开始 Phase 1（PRD）**：

- [ ] 已验证 3+ 人愿意付费
- [ ] 有清晰的手动流程（写在纸上）
- [ ] 知道 MVP 的最小范围
- [ ] 知道该构建什么，不该构建什么

**不满足？** 继续 Phase 0，不要写代码。

---

## ✅ Phase 0 验收标准

- [ ] 能描述具体的目标用户（名字、职业、痛点）
- [ ] 已与 10+ 潜在客户交流
- [ ] 3+ 人表示愿意付费（或已付费）
- [ ] 手动流程已写在纸上
- [ ] MVP 范围明确（能在一个周末发布）
- [ ] 定价策略确定

**验收通过后，进入 Phase 1: PRD →**

---

## 📋 与后续 Phase 的关系

```
Phase 0: Business Validation
    ↓ 输出：验证的想法 + 手动流程
Phase 1: PRD
    ↓ 输出：产品需求文档
Phase 2: Architecture
    ↓ 输出：技术架构
...
Phase 6: Implementation
    ↓ 输出：可运行产品
Phase 7: Review & Deploy
    ↓ 输出：上线产品
Phase 8: First Customers
    ↓ 获取前 100 个客户
```

**记住**：Phase 0 的成功标准是"知道该构建什么"，不是"构建了什么"。
