# 附录：知识管理与会话恢复

> 借鉴 claude-code-system-prompts 的 Session Search 和 Compact Service  
> 用于长周期项目管理和跨会话知识保持

---

## A.1 会话标记与分类 (Session Tagging)

### 标记系统

为每个开发会话添加标签，便于后续检索：

| 标签类型 | 示例 | 用途 |
|---------|------|------|
| **功能标签** | `feature/payment`, `feature/auth` | 按功能模块分类 |
| **阶段标签** | `phase/impl`, `phase/debug` | 按开发阶段分类 |
| **优先级标签** | `p0`, `p1`, `p2` | 按优先级分类 |
| **状态标签** | `blocked`, `wip`, `review` | 按当前状态分类 |

### 标记命令示例

```bash
# 在会话开始时标记
/tag feature/payment phase/impl p0

# 多个标签
/tag architecture-decision solana-integration
```

## A.2 会话搜索 (Session Search)

### 搜索策略

当需要回顾历史决策时，按优先级搜索：

1. **精确标签匹配** (最高优先级)
   - 搜索完全匹配的标签
   - 例：搜索 `feature/payment` 找到所有支付相关会话

2. **部分标签匹配**
   - 搜索标签相关术语
   - 例：`payment` 匹配 `feature/payment`, `bug/payment-flow`

3. **分支匹配**
   - 搜索特定 Git 分支的会话
   - 例：`branch: feature/payment-v2`

4. **内容匹配**
   - 搜索会话标题、摘要、转录内容
   - 例：`"database schema"`

5. **语义相似性**
   - 搜索概念相关的内容
   - 例：`testing` 匹配 `tests`, `unit tests`, `QA`

### 搜索查询模板

```
搜索: "[关键词或问题]"

检查:
- [ ] 标签匹配
- [ ] 分支相关
- [ ] 技术决策
- [ ] 错误解决方案
- [ ] 架构讨论
```

## A.3 上下文压缩 (Compact Service)

### 何时压缩

当项目会话过长时（>50 轮对话），进行上下文压缩：

| 触发条件 | 操作 |
|---------|------|
| 接近上下文限制 | 完整压缩整个会话 |
| 新增大量消息 | 仅压缩新消息 |
| 恢复旧会话 | 压缩旧消息，保留最新消息 |

### 压缩内容模板

```markdown
## 会话摘要 [日期]

### 1. 主要请求和意图
- 原始需求: 
- 当前阶段: 

### 2. 关键技术概念
- 使用的技术/框架:
- 架构模式:
- 设计决策:

### 3. 文件和代码变更
| 文件 | 操作 | 关键代码 |
|------|------|---------|
| | 创建/修改 | |

### 4. 错误和修复
| 错误 | 原因 | 解决方案 |
|------|------|---------|
| | | |

### 5. 问题解决
- 已解决:
- 进行中:
- 待解决:

### 6. 用户所有指令
1. 
2. 

### 7. 待办事项
- [ ] 
- [ ] 

### 8. 当前工作
正在处理: 

### 9. 下一步（如明确）
建议: 
```

### 压缩策略

**完整压缩**: 整个会话压缩为单个摘要
- 适用：会话结束、长期存档

**部分压缩**: 保留近期消息，压缩旧消息
- 适用：会话进行中、需要保留上下文

**渐进压缩**: 多层摘要
- 适用：超长项目（>100 轮）
- 例：第一层（最新 20 轮）→ 第二层（21-50 轮摘要）→ 第三层（更早摘要）

## A.4 会话恢复 (Session Recovery)

### 中断后恢复流程

当开发中断后恢复时：

1. **阅读实现日志**
   ```bash
   # 查看 Phase 6 记录
   cat docs/06-implementation-log.md
   ```

2. **检查当前状态**
   ```bash
   # Git 状态
   git status
   
   # 未完成的测试
   cargo test 2>&1 | grep "FAILED"
   ```

3. **回顾任务拆解**
   - 查看 Phase 4 Task Breakdown
   - 确认当前进行中的任务

4. **加载压缩摘要**
   - 如果有会话摘要，优先阅读
   - 否则搜索相关历史会话

### 恢复检查清单

- [ ] 已阅读 06-implementation-log.md
- [ ] 已确认 Git 状态（分支、未提交变更）
- [ ] 已回顾当前任务状态
- [ ] 已运行测试确认当前状态
- [ ] 已加载相关历史上下文

## A.5 知识沉淀 (Skillify)

### 将经验转化为可复用技能

项目结束后，将可复用的流程提炼为技能：

### 技能创建流程

1. **识别可复用模式**
   - 哪些步骤在不同项目中重复？
   - 哪些检查清单特别有效？
   - 哪些调试流程是通用的？

2. **记录技能规格**

```markdown
---
name: [技能名称]
description: [一句话描述]
tags: [相关标签]
---

## 触发条件
何时使用这个技能？

## 前置条件
需要什么准备？

## 执行步骤
1. 
2. 
3. 

## 验证标准
怎么确认执行成功？

## 常见问题和解决
| 问题 | 解决方案 |
|------|---------|
| | |
```

3. **存储位置**
   - 项目级：`.claude/skills/`
   - 用户级：`~/.claude/skills/`

### 示例技能

- `solana-program-test`: Solana 程序测试流程
- `react-component-create`: React 组件创建规范
- `security-audit-checklist`: 安全审计检查清单

## A.6 故障诊断 (Stuck Skill)

### 当开发卡住时的诊断流程

```markdown
## 诊断检查清单

### 1. 进程状态
- [ ] 检查当前进程 CPU/内存使用
- [ ] 检查是否有僵死子进程
- [ ] 检查是否有进程等待 stdin

### 2. 资源检查
- [ ] 磁盘空间充足 (>10%)
- [ ] 内存充足 (>20%)
- [ ] 文件描述符未泄漏

### 3. 网络检查
- [ ] API 端点可达
- [ ] 无网络超时
- [ ] 依赖服务正常

### 4. 错误检查
- [ ] 查看最近 stderr 输出
- [ ] 检查日志文件
- [ ] 查看工具调用错误

### 5. 状态一致性
- [ ] Git 状态干净或已知
- [ ] 文件系统状态符合预期
- [ ] 环境变量正确

## 诊断结果

| 一致性 | ✅/❌ | |

## 建议行动
基于诊断结果，建议：
1.
```

## A.7 使用建议

### 小型项目 (< 1 周)
- 使用基本的会话标记
- 必要时进行简单压缩

### 中型项目 (1-4 周)
- 系统使用标签分类
- 每周进行上下文压缩
- 项目结束创建技能

### 大型项目 (> 1 月)
- 完整使用所有功能
- 定期搜索历史决策
- 建立团队知识库

---

*知识管理是长期效率的关键。花 5 分钟记录，节省未来数小时的重新理解。*
